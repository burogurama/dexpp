# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`dex++` is an early-stage C++23 library for static analysis of Android DEX files. There is no stable release yet; the public API is the single header `src/dex.hpp`.

## Build & test

CMake + GoogleTest (fetched at configure time via `FetchContent`). Targets:

- `dexpp_core` — static library (PIC) holding every `src/**` source; the other targets link it
- `main_test` — small CLI driver in `src/main.cpp` that disassembles a DEX file (`./main_test <file.dex>`)
- `unit_tests` — GoogleTest binary aggregating every `tests/**/*.cc`
- `dexpp` — Python extension module (pybind11, fetched via `FetchContent`); only built with `-DDEXPP_BUILD_PYTHON=ON`
- `dexpp_c` — static C ABI shim (`build/libdexpp_c.a`) over `bindings/c/dexpp.h`, for Go/cgo and other FFI consumers; built by default (`-DDEXPP_BUILD_C=ON`)

```bash
cmake -S . -B build
cmake --build build -j

# Run all tests — MUST be invoked from the project root because
# CMakeLists.txt sets WORKING_DIRECTORY ${CMAKE_SOURCE_DIR} for gtest_discover_tests
# and the tests open fixtures via the relative path "tests/data/*.dex".
ctest --test-dir build --output-on-failure

# Run the test binary directly (also from project root):
./build/unit_tests

# Run a single test or filter (gtest syntax):
./build/unit_tests --gtest_filter='ParseAnyDexTest.*'
./build/unit_tests --gtest_filter='ShapesHierarchy.ImplementersOfShape'

# Disassemble a DEX file with the demo CLI:
./build/main_test tests/data/classes.dex

# Python bindings: build and run their tests (also from project root):
cmake -S . -B build -DDEXPP_BUILD_PYTHON=ON && cmake --build build -j
PYTHONPATH=build python3 bindings/python/test_dexpp.py

# Go bindings: build the C shim first, then run the Go tests:
cmake --build build --target dexpp_c -j
cd bindings/go && go test ./...
go run ./example ../../tests/data/sample.apk   # demo CLI
```

DEX fixtures live in `tests/data/` (`classes.dex`, `multistring.dex`, `shapes.dex`, `trycatch.dex`, `fibonacci.dex`, `polymorphic.dex`, `inherit.dex` + its `inherit_a`/`inherit_b` cross-DEX split), each alongside the `.java` source it was compiled from (build new ones with `javac --release 8` + `d8`; pass `--min-api 24` when the fixture uses default interface methods, or d8 desugars them away). APK fixtures `app.apk` (multidex: classes.dex + fibonacci.dex, mixed deflate/stored), `multidex.apk` (classes..classes4 deflated + classes5 stored — enough deflated entries to take the parallel load path) and `nodex.apk` are zips of the DEX fixtures. New tests should add fixtures here and reference them via the same `tests/data/...` relative path. Tests that need a crafted archive (size mismatches, duplicate names, bad streams) build it in memory with `tests/raw/zip_builder.hpp` instead. DEFLATE decoding uses [libdeflate](https://github.com/ebiggers/libdeflate), fetched at configure time (pinned by `URL_HASH`) and compiled *into* `dexpp_core` — not linked as a separate library — so `libdexpp_core.a` stays self-contained for the Go static link and the wheel. There is no zlib dependency.

Code style is enforced by `.clang-format` (LLVM base, 4-space indent, 100-column limit, custom brace wrapping with `AfterFunction: true` / `AfterClass: true`) and gated in CI (the `format` job runs `clang-format-18 --dry-run -Werror` over every tracked `*.cc/*.cpp/*.hpp/*.h`). **The pinned version is clang-format-18** — a different major version reflows enough to fail the gate, so format with `clang-format-18` locally before pushing (`git ls-files '*.cc' '*.cpp' '*.hpp' '*.h' | xargs clang-format-18 -i`).

**CI, sanitizers, fuzzing.** `.github/workflows/ci.yml` runs on every push/PR: build+test on a gcc-13 and clang-19 matrix, an ASan+UBSan job and a TSan job (`-DDEXPP_SANITIZE=<sanitizers>` — a directory-wide sanitizer option), the Python + Go bindings, and a 60s smoke over the four libFuzzer harnesses in `fuzz/`. `fuzz-nightly.yml` runs longer sessions with a cached corpus. The TSan job pins the concurrent-reads contract: one `AnalysisContext`'s lazy caches and `call_once` singletons are safe to read from many threads at once — exercised by `tests/analysis/threaded_stress_test.cc`, which races threads through first-access lazy init. TSan needs `vm.mmap_rnd_bits` lowered on newer kernels (the CI job and any local `-DDEXPP_SANITIZE=thread` run both do `sudo sysctl -w vm.mmap_rnd_bits=28` first, since `gtest_discover_tests` runs the instrumented binary at build time). Building against **Clang requires Clang ≥ 19**: earlier Clang reports `__cpp_concepts=201907`, which guards libstdc++'s `<expected>` out — Clang 19 bumped the macro, so the project (and the fuzzers, `-DDEXPP_BUILD_FUZZERS=ON`, Clang-only) build against plain libstdc++ with no libc++. Fuzz targets and seeds are documented in `fuzz/README.md`.

## Architecture

Three layers, three namespaces, dependencies flowing strictly downward (`apk → analysis → raw`). **Always pick the right layer:** parser/format work touches `dex::raw::`; code analysis is `dex::` (the analysis layer); package-level metadata (manifest, archive entries, resources) is `dex::apk::`. The public umbrella is `src/dex.hpp`. `raw::*` types are kept out of analysis-layer signatures with one deliberate exception: the low-level builder `dex::build_cfg(const raw::CodeItem&, span<const Instruction>)` in `analysis/cfg.hpp` — consumers should use `Method::cfg()` instead.

The split between `dex::apk::Apk` and `dex::AnalysisContext` is deliberate: an `Apk` is a *package* (archive bytes + manifest + resources), an `AnalysisContext` is its *code*. They are separate objects with separate lifetimes — do NOT fold manifest/resource accessors onto `AnalysisContext` (that recreates androguard's god-object). The bridge is one-directional: `Apk::analysis()` produces an `AnalysisContext`; the analysis layer never reaches up into `apk`.

### Layer 1 — `src/raw/` (`namespace dex::raw`): stateless parser

Free functions in `namespace dex::raw::parser` (in `raw/parser.hpp`). Every function takes `std::span<const uint8_t> buf` plus an offset and returns `std::expected<T, ParseError>`. There is no internal state, no offset tracking, no caches — parsing is a pure function of the buffer.

**Untrusted-input hardening (the library parses adversarial APKs):** all bounds arithmetic on a `uint32_t` offset must be overflow-safe — use the subtractive form (`offset > size || size - offset < N`) or cast offset to `std::size_t`, never `offset + N > size` (a near-`UINT32_MAX` offset wraps and bypasses the check). The analysis layer never indexes the raw id tables (`string_ids`/`type_ids`/`proto_ids`/`method_ids`/`field_ids`) directly: it goes through the bounds-checked impl accessors (`string_of`, `type_descriptor_of`, `proto_descriptor_of`, `method_id_of`, `field_id_of`, and the `method_item`/`field_item`/`proto_item` pointer helpers), which return an empty string / empty identity / nullptr on an out-of-range index — the uniform "malformed pool index → empty result" policy. Out-of-range indices reach these from bytecode (const-string/const-class) and from lazily-decoded `class_data`, so the checks can't be skipped by a parse-time pass. A second amplification class: an attacker-controlled element count (a ULEB128 in `class_data`/`code_item`, a `u32` in the annotations directory) must never drive a bare `vec.reserve(count)` — a few bytes encoding `0xFFFFFFFF` would trigger a multi-GB speculative allocation before any element is read. Use the `reserve_bounded()` helper in `parser.cpp` (clamps the count to `remaining_bytes / min_element_size`); the fixed-size id tables are instead guarded by an up-front `count * elem_size` truncation check. `tests/raw/malformed_test.cc` is the regression corpus (the `*DoesNotOverAllocate` cases pin this — they `bad_alloc` pre-fix); run the suite under `-fsanitize=address` in CI, and the `fuzz_apk` harness (which drives the lazy analysis decode) is what surfaced it. This was a deliberate redesign; the rationale is documented in `PARSER_API_DESIGN.md` (note: that doc is aspirational and uses some names — e.g. `DEXFile`, the old `Parser` class — that differ from what landed; treat code as authoritative).

`raw::DexFile` (in `raw/types.hpp`) is the parsed-data container. Its constructor is private and `parser::parse_buffer` is the sole `friend` — instances are produced only via `parser::parse_buffer` / `parser::parse_file`. Accessors hand out `std::span` views into internal vectors; the `DexFile` must outlive any spans returned. The friend declaration uses a forward-declared `parser::parse_buffer` near the top of `raw/types.hpp`, which is why `types.hpp` includes `<expected>` and `raw/error.hpp`.

The `raw/types.hpp` structs (`Header`, `MapList`, `ProtoIdItem`, `ClassDefItem`, `ClassDataItem`, `CodeItem`, `TryItem`, etc.) mirror the on-disk DEX format described in `DOCS/dex_file_format.md`. Keep them faithful to the spec — analysis-layer abstractions belong in layer 2.

### Layer 2 — `src/analysis/` (`namespace dex`): handle-based analysis API

The single user-facing entry point is `dex::AnalysisContext`, created via `from_dex(path)`, `from_dex_files(paths)`, or `from_apk(path, ApkLoadOptions{})` (extracts top-level `classes*.dex` in multidex order via the minimal ZIP reader in `raw/zip.hpp` — no ZIP64, stored/deflate only; a name repeated in the central directory loads only its first entry). Decompression dominates APK load time, so when ≥ 3 DEX entries are deflated, `from_apk_buffer` decompresses + parses them on a per-call `std::jthread` pool (`ApkLoadOptions::threads`: 0 = auto, 1 = serial; no global pool — it would not survive `fork()`). The parallel path must stay observably identical to the serial one: results are committed in multidex order, entries after the first failure are skipped, the reported error is the first in multidex order, and worker exceptions are captured and rethrown on the calling thread (an exception escaping a `std::thread` would `std::terminate` the host process). `raw::zip::read_entry` is thread-safe: libdeflate selects its CPU-specific decoder via plain non-atomic globals on first use, so `init_libdeflate_once()` does a dummy decompression under `call_once` first — keep that, or the TSan job flags the race. Its public surface: `classes()`, `strings()` (the whole string pool, complementing `Xrefs::referenced_strings()`), `find_class(descriptor)` (returns `std::optional<Class>`), `call_graph()`, `class_hierarchy()`, `xrefs()`. Everything else is internal.

PIMPL split:
- `src/analysis/analysis_context.hpp` — public header. Only forward-declares `dex::detail::AnalysisContextImpl`.
- `src/analysis/analysis_context_impl.hpp` — **private** header (do not include from public code). Contains the full `detail::AnalysisContextImpl` definition plus its lazy caches and helpers (`get_class_data`, `get_code_item`, `get_instructions`, `get_cfg`, `find_class_index`, `string_of`, `type_descriptor_of`, `buffer_of`, `get_call_graph`, `get_class_hierarchy`, `get_xrefs`, and the identity builders `proto_descriptor_of` / `method_id_of` / `field_id_of` shared by the graph builders). Included by `analysis_context.cpp` and by the handle / graph-builder `.cpp` files.
- Per-DEX `DexSlot` holds five lazy caches behind dedicated mutexes: `class_data_cache`, `code_item_cache`, `instructions_cache`, `cfg_cache`, and `string_cache`. All rely on `std::unordered_map`'s reference-stability guarantee for mapped values, since handles return raw pointers / spans / references into them. A sixth impl-wide mutex-guarded cache (`proto_descriptor_cache`) memoizes full prototype descriptors.
- **Memory model & laziness.** `from_dex`/`from_dex_files`/`from_apk` do the minimum up front: each `DexSlot`'s bytes are held in a `detail::ManagedBuffer` that prefers a read-only `mmap` (so the OS pages in only what an analysis touches) and falls back to a heap read where mapping is unsupported; APK entries are inflated to heap buffers and the archive mapping is released. The loaders parse with `raw::parser::ParseOptions{.decode_strings = false}`, so the **string pool is never eagerly decoded** — `string_of()` decodes one string at a time into `DexSlot::string_cache` on first use (a malformed entry caches as empty rather than failing the load). `type_descriptor_of` and `build_class_index` go through `string_of`, so even loading the class-name table only materializes the strings it needs. Everything expensive (class data, code items, instructions, CFGs, call graph, hierarchy, xrefs) is built only when first requested and then cached. Keep this invariant: a new loader path must not walk the whole program, and the raw `parse_buffer` default stays eager (the raw layer's own tests and `parse_file` rely on `strings()` being populated).
- Four whole-program lazy singletons are built via `std::call_once` on first access: the class-name → `(dex_idx, class_def_idx)` lookup table (first `find_class_index()`), the `CallGraph`, the `ClassHierarchy`, and the `Xrefs` index.

Handle lifetime — **important**:
- `Class`, `Method`, `Field`, `ClassRef` are non-owning handles, each storing `std::shared_ptr<const detail::AnalysisContextImpl>` plus indices. They keep the implementation alive for their own lifetime, so a handle survives the destruction of every `AnalysisContext` wrapper it was derived from. Tests in `tests/analysis/analysis_context_test.cc` (`LifetimeTest.*`) pin this invariant.
- Default-constructed handles are "null" (`is_valid() == false`) and only `is_valid()` and the default constructor itself may be called on them.
- `ClassRef::resolve()` returns `Class` by value, using the default-constructed null handle as the not-found sentinel (no heap allocation; check via `is_valid()`).

Method-level data:
- `Method::instructions()` returns `std::span<const Instruction>` viewing the per-context decoded-instructions cache. Repeated calls hit the cache and return the same span — `s1.data() == s2.data()`.
- `Method::cfg()` returns `const Cfg&` from the per-context `cfg_cache`; repeated calls return the same reference.
- **Forward references** (`Method::calls()`, `field_accesses()`, `string_loads()`, `type_uses()`) walk the cached instruction stream and resolve pool indices to identities (`MethodCall`/`FieldAccess`/`StringLoad`/`TypeUse` in `method.hpp`). They are the per-method "xref-to" complement of the whole-program reverse index in `AnalysisContext::xrefs()`; not cached (cheap, O(method)). `Method::try_blocks()` decodes try regions + handlers (`TryBlock`/`CatchHandler`, with `catch_all_offset` for finally), reusing the handler-resolution pattern from `cfg.cpp`.
- **Register frame** (`Method::register_count()`, `parameter_registers()`): `register_count` is the frame's `registers_size`; `parameter_registers()` resolves the Dalvik incoming-args convention (args occupy the last `ins_size` registers) into `ParameterRegister{reg, type, is_this, is_wide}` — implicit `this` first for instance methods, declared params in order, wide (long/double) params occupying a register pair. Both return 0/empty for abstract/native methods. Needed by register-level dataflow consumers (e.g. a taint engine seeding from parameter registers). Note: takes the `this` type from `type_descriptor_of` (a stable cache view), NOT from `declaring_class()` — `ClassRef` owns its descriptor, so a view into a temporary `ClassRef` would dangle.
- Rendering: `dex::opcode_name(uint8_t)` and `dex::to_string(const Instruction&)` (free functions in `instruction.hpp`) give the mnemonic and a full "`<mnemonic> <operands>`" string with raw pool indices (`string@N`, `method@N`, …). `src/main.cpp` is now a thin demo over `to_string`. `to_string`'s operand renderers must stay in sync with the 24 instruction variants.
- **Annotations & initial values** (`analysis/annotations.hpp`): `Class`/`Method`/`Field::annotations()` return resolved `Annotation{type_descriptor, visibility, elements}`; element values are owned `AnnotationValue` variants (widened primitives, `std::string`, `TypeRef`/`EnumRef`/`FieldRef`/`MethodRef` wrappers, arrays, boxed nested annotations) — independent of the context's lifetime. Elements left at `@interface` defaults are absent (defaults live in `dalvik.annotation.AnnotationDefault`); `Annotation::find(name)` returns nullptr for them. `Field::initial_value()` resolves the static-values encoded array (nullopt ⇒ type default). All parsed on demand, uncached. Raw side: `raw::EncodedValue` (recursive, move-only because of the boxed annotation alternative) + `parse_encoded_value/array/annotation/annotation_item` in `raw/parser.hpp`, recursion-bounded at depth 64. Method/Field handles reach their class_def via `impl->class_def_of_type` (same-DEX linear scan — deliberately not the cross-DEX name index).
- Abstract/native methods (`code_off == 0`): `Method::has_code() == false`, `instructions()` returns an empty span, `cfg()` returns an empty `Cfg`.
- `Instruction` is a 24-alternative `std::variant` over typed structs (`NopInstruction`, `GotoInstruction`, `InvokeInstruction`, `MoveInstruction`, …) defined in `analysis/instruction.hpp`. Every variant has an `InstructionBase base` field; use `dex::base_of(insn)` to access shared fields (`offset`, `opcode`, `size`) without a visit. See `src/main.cpp` for the canonical `std::visit` dispatch pattern over every variant.

Graph analyses (`analysis/cfg.hpp`, `analysis/call_graph.hpp`, `analysis/class_hierarchy.hpp`):
- `Cfg` — per-method control-flow graph. `blocks()` are sorted by `start_offset` with the entry block at index 0; edges reference target blocks by index (`CfgEdge{target_block, kind, label}` with `EdgeKind` covering fallthrough, goto, branch taken/not-taken, switch case/default, and exception edges). `BasicBlock::first_insn`/`insn_count` index into the method's decoded instruction span.
- `CallGraph` — whole-program, lazy, **move-only**. Nodes are identified by `MethodId` (class descriptor, name, full proto descriptor — deliberately not shorty, which would collide overloads). Unresolved nodes (`resolved == false`) represent external methods; `method_for(node)` materializes a `Method` handle for resolved nodes (holds a `weak_ptr` to the impl, so it returns nullopt if the context died). Edges carry an `EdgeOrigin`: each call site gets exactly one `Declared` edge, plus (for virtual/interface) `ChaOverride` edges — one per distinct dispatch target among the declared class's loaded descendants, including what non-overriding descendants *inherit* (possibly from outside the declared class's subtree) — plus at most one `InheritedResolution` edge when the declared class defines no matching method: the nearest loaded definition per Dalvik resolution (superclass chain nearest-first with an internal cycle guard, then transitive superinterfaces preferring defaults over abstract declarations; applies to virtual/interface/super/static, static via the chain only). All edges of a site share `code_offset` and kind; non-`Declared` edges always target resolved nodes. If no loaded ancestor defines the method the node just stays unresolved. `invoke-polymorphic` stays declared-target only; the build order B (declared) → B2 (CHA) → B3 (upward) is load-bearing — B2/B3 must only scan `Declared` edges. Documented divergences from ART live in `call_graph.hpp`'s class comment. Duplicate `MethodId`s across DEX files follow Android's last-loaded-wins rule. Fixture: `tests/data/inherit.dex` (+ `inherit_a`/`inherit_b` split pair for cross-DEX resolution; source `Inherit.java`, built with `d8 --min-api 24` — the default min-api desugars default methods into companion classes and would invalidate the interface-resolution tests).
- `ClassHierarchy` — whole-program, lazy, **move-only**. Descriptor-keyed queries (`supertypes`, `superclass_of`, `direct_interfaces`, `subclasses`, `implementers`, `all_supertypes`, `all_descendants`, `is_subtype_of` — reflexive, `is_loaded`, `is_interface`). External supertypes (e.g. `Ljava/lang/Object;`) get descriptor-only nodes with `is_loaded() == false`. Query results are `std::string_view`s into the hierarchy's own storage, valid for the lifetime of the `AnalysisContext`.
- `Xrefs` (`analysis/xrefs.hpp`) — whole-program cross-reference index, lazy, **move-only**. Answers "who references X": `method_refs(MethodId)` / `method_refs_by_name(name)` for invoke sites (literal declared targets, no CHA fan-out — use the call graph for dispatch), `field_refs`/`field_reads`/`field_writes` keyed by `FieldId` (class descriptor, name, type), `string_refs(value)` + `referenced_strings()` for const-string loads, and `type_refs(descriptor)` for const-class/check-cast/instance-of/new-instance/new-array/filled-new-array (`TypeRefKind`). Every site carries a `referrer` index; `referrer_id()` gives its `MethodId`, `referrer_method()` materializes a `Method` (nullopt if the context died — `weak_ptr` internally, same as `CallGraph`).

### Python bindings (`bindings/python/`)

`dexpp_module.cpp` is a single pybind11 translation unit mirroring `src/dex.hpp`; `test_dexpp.py` is its test suite (plain `python3` runnable, pytest-compatible). Binding conventions: `std::expected` errors raise `FileNotFoundError`/`ValueError`; null handles and not-found sentinels become `None`; **`TypeDescriptor` is flattened to `str`** because unlike the other handles it does not keep the context alive; small span accessors copy into lists, but the whole-program index tables — `CallGraph.nodes`/`edges`, `Xrefs.referrers`, `Cfg.blocks` — are **zero-copy sequence views** (`bind_view` in `dexpp_module.cpp`: O(1) indexing, elements built on access, the view holds the owning Python object so the context stays alive). Never bind one of those as a list-returning property again: the tables cross-reference each other by index, so `cg.nodes[e.callee_node]` in a loop copied the whole table per edge (hours on a mid-size APK). Call-graph `CallNode`/`CallEdge` are handles (`NodeRef`/`EdgeRef`: owner + graph + index) with direct navigation (`edge.caller`/`callee`, `node.out_edges`/`in_edges`, `node.method`); `CallEdgeView.where(origin=, kind=)` filters in C++ — needed because CHA fan-out is ~95%+ of edges on real apps (≈50M on a large one), far too many to filter per edge in Python. The lazy singletons (`call_graph`, `class_hierarchy`, `xrefs`, `cfg`) are bound with `return_value_policy::reference_internal`. `AnnotationValue` converts to native Python (None/bool/int/float/str/list, `*Ref` classes, nested `Annotation`). **When the C++ API changes, update the bindings, the `dexpp.pyi` stubs, and `test_dexpp.py` in the same commit** — the three must stay in lockstep.

### C ABI & Go bindings (`bindings/c/`, `bindings/go/`)

`bindings/c/dexpp.h` + `dexpp_c.cpp` form the interop boundary for non-C++ consumers — a deliberately small subset of the C++ API (loading, manifest package/components with exported/reachable, class enumeration/lookup, string pool, per-class methods). Instruction-level disassembly, the call graph, and xrefs are *not* in the shim yet; extend it as needed. Conventions (keep them when extending): opaque handle pointers (`DexppContext`/`DexppClass`/`DexppMethod`/`DexppApk`); fallible functions take `char **err` and return NULL on failure with a malloc'd message; every returned string/array is a malloc'd copy freed via `dexpp_string_free` / the matching `*_array_free`; Class/Method handles keep the analysis alive after the context handle is freed (mirrors the C++ handle-lifetime model).

`bindings/go/dexpp` (module `github.com/burogurama/dexpp/bindings/go`) wraps the shim via cgo. Its `LDFLAGS` reference `build/libdexpp_c.a` + `build/libdexpp_core.a` by `${SRCDIR}`-relative path, so the C shim **must be built first** (`cmake --build build --target dexpp_c`) and the build directory must be named `build/`. The C++ runtime links statically (`-lstdc++`) — resulting Go binaries need only libc. Go handles are freed by GC finalizers with an eager `Close()`; strings and `[]Component` are copied into Go. Tests reach fixtures via the relative path `../../../tests/data`, so they run from anywhere `go test` puts them (the package dir). **When extending the C ABI, update `dexpp.h`, `dexpp_c.cpp`, the Go wrapper, and `dexpp_test.go` together** — same lockstep rule as the Python bindings.

### Packaging, stubs, benchmarks

- **Wheel**: `pyproject.toml` uses scikit-build-core; `pip install .` builds the extension (needs C++23, CMake ≥ 3.18). CMake gates on `SKBUILD`: a wheel build forces `DEXPP_BUILD_PYTHON=ON` / `DEXPP_BUILD_TESTS=OFF` (no googletest fetch, no demo CLI). The two `option()`s otherwise default to dev mode (tests on, python off).
- **Version & releases**: `src/version.hpp` (`DEXPP_VERSION`) is the single source of the version — CMake parses it into `project(VERSION)`, scikit-build-core's regex provider reads it into the wheel metadata, and the module exposes it as `dexpp.__version__`. To release: bump `version.hpp`, add a `## <version>` section to `CHANGELOG.md`, and push a `v<version>` tag. `.github/workflows/release.yml` then builds cibuildwheel wheels (Linux x86_64 manylinux + musllinux; Python versions and the per-wheel test run are in `[tool.cibuildwheel]` in `pyproject.toml`) plus the sdist, checks the tag against `version.hpp`, and creates the GitHub release with that changelog section as notes. dexpp is **not published to PyPI**; the README installs from the release page with `pip --no-index --find-links` (keep `--no-index`, or pip could pick an unrelated `dexpp` from PyPI). The sdist excludes `tests/`, `fuzz/`, `bench/`, `.github/` (`sdist.exclude`).
- **Stubs**: `bindings/python/dexpp.pyi` is hand-written and installed two ways — a sibling `.pyi` (pyright) and a `dexpp-stubs/__init__.pyi` PEP 561 package (mypy). Keep it in sync with the bindings.
- **Migration**: `DOCS/androguard_migration.md` maps androguard calls to dexpp; README has install/usage.
- **Benchmarks** (`bench/`): `gen_bench_apk.sh N` codegens an N-class APK (gitignored), `bench_vs_androguard.py` times both libraries. The fair metric is the cold end-to-end row — dexpp is lazy (cheap load, pays on first query), androguard is eager, so isolated load/enumerate rows mislead in isolation. `bench_usecases.py` complements it: each (library, use case) pair runs in a fresh subprocess so every number is a true cold-start cost (wall-clock + peak RSS), with each library's answer cross-checked against the other's.

### Layer 3 — `src/apk/` (`namespace dex::apk`): package metadata

`Apk::open(path)` loads the archive bytes once and is the entry point. It's a thin handle over a shared `detail::ApkImpl` (cheap to copy). Three lazy products, all `std::call_once`-cached on the impl:
- `entries()` / `read(name)` — archive listing and raw entry extraction via `raw::zip`.
- `manifest()` — returns `const Manifest*` (nullptr if absent/undecodable). `apk/axml.hpp` is a generic binary-XML (AXML) decoder → `axml::XmlDocument` (owned-string tree, `XmlNode`/`XmlAttribute` with typed-value accessors `as_string`/`as_int`/`as_bool`/`as_reference`). `apk/manifest.hpp` is the typed triage view over that tree: `package`, `version_code/name`, `min/target_sdk`, `permissions`, `declared_permissions`, `declared_permission_protection_level(name)`, `components()` (+ `components_of(kind)`), `launcher_activity`, `debuggable`, `allow_backup`, plus `xml()` as an escape hatch for unsurfaced attributes. `Component::is_exported()` returns the explicit `android:exported` or infers it (any intent-filter ⇒ exported); component names are qualified against the package. `Component::is_reachable()` is the attack-surface predicate — exported AND not gated behind an app-declared `signature`/`signatureOrSystem` permission (a third-party app can hold `normal`/`dangerous` perms, not signature; permissions whose level the manifest doesn't declare, e.g. platform perms, are treated as reachable). The signature gate is resolved at parse time into `Component::guarded_by_signature_permission`. Fixture: `tests/data/reachable.apk` (source `ReachableManifest.xml`) declares permissions at every protection level and guards exported components with them.
- `resources()` — returns `const ResourceTable*` (nullptr if absent/undecodable). `apk/resources.hpp` decodes `resources.arsc`: `resolve_string(id)` (string-typed forward resolution through the global value pool), `name_of(id)` → `ResourceName{package,type,entry}`, `id_of(type, entry)` reverse lookup. Config variants (locale/density) collapse to the default-config value. `Apk::resolve_string(ref)` is the convenience for resolving a manifest `@string/...` reference (take an attribute's `as_reference()`, pass it here). Handles non-sparse / sparse / OFFSET16 entry tables.
- The AXML and ARSC decoders share `apk/string_pool.{hpp,cpp}` (`detail::parse_string_pool` + `rd16`/`rd32` over the RES_STRING_POOL chunk) — don't re-implement string-pool decoding. Same untrusted-count hardening as the DEX parser applies: a string entry's UTF-16 length is attacker-controlled (up to ~2^31 via the high-bit extension), so `decode_utf16` clamps its `reserve` to the code units the buffer can supply. `fuzz_apk`/`fuzz_axml` under `-malloc_limit_mb` guard this class in CI.
- `signing()` — returns `const SigningInfo&` (never fails; unsigned ⇒ `is_signed() == false`). `apk/signing.hpp` detects v1 (JAR `META-INF/*.RSA|DSA|EC`), v2, and v3/v3.1 (APK Signing Block before the central directory, located via `raw::zip::central_directory_offset`) and extracts X.509 `Certificate`s (subject/issuer DNs in DER order, serial, validity as ISO strings, SHA-1/SHA-256 fingerprints of the DER), de-duplicated by SHA-256 across schemes. **Identification only — digests/signatures are NOT verified**; keep that boundary (verification belongs to apksigner, not this library). `signing.cpp` contains self-contained SHA-1/SHA-256 and a minimal DER TLV walker — extend those rather than adding a crypto dependency.
- `analysis()` — bridges to `AnalysisContext::from_apk_buffer(bytes)` (reuses the already-loaded archive; no re-read). `from_apk_buffer` is the shared multidex builder; `AnalysisContext::from_apk(path)` is the convenience that reads then delegates to it.

Fixtures: `tests/data/sample.apk` is a real `aapt2`-compiled APK (binary manifest + `resources.arsc` with `@string/app_name`/`greeting` + a `classes.dex`; the manifest's `android:label` is a `@string/app_name` reference so the manifest→resource resolution path is exercised end to end). `SampleManifest.xml` alongside is its source. `signed.apk` is `sample.apk` signed v1+v2+v3 with a throwaway RSA key (CN=Dexpp Test) — use the **SDK build-tools `apksigner`** (`~/Android/Sdk/build-tools/36.0.0/apksigner`), not the older Debian `/usr/bin/apksigner` which lacks `--v3-signing-enabled`; expected fingerprints in `signing_test.cc` are openssl ground truth. Rebuild APK fixtures with `aapt2 compile`/`link` against an `android.jar` platform (e.g. `~/Android/Sdk/platforms/android-34/android.jar`), never by hand — the AXML/ARSC formats are what's under test.

### Adding a new source file

Library sources are **explicitly listed** in the `dexpp_core` target in `CMakeLists.txt` (not glob); any new `.cpp` under `src/` must be added there (one place — all other targets link `dexpp_core`, including the wheel build). Test sources are picked up automatically by `GLOB_RECURSE` from `tests/*.cc`, but a **reconfigure is needed** for new test files to appear (`cmake -S . -B build`). The test/CLI targets live under `if(DEXPP_BUILD_TESTS)`, the python module under `if(DEXPP_BUILD_PYTHON)`, and the C shim under `if(DEXPP_BUILD_C)`; a default `cmake -S . -B build` builds tests and the C shim but not python.
